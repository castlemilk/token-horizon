# Track 5 backend audit — Token Horizon

Audit date: 18 November 2026. Repository: `castlemilk/token-horizon`; branch `main`; exact commit `b468206e9378c8d7a6788b67072494982e7de17d` (repository commit timestamp 2026-11-18T07:35:19Z).

This is read-only research. Findings below are **source-observed** unless explicitly marked **synthetic reproduction**. No application server was run, no production usage or private prompts were requested, and no repository/issue/settings mutation was made. Local source evidence is an internal research input, not a deliverable: some public source files contain starter-profile data or comments referring to historical usage. Do not bundle the `source/` directory into user-facing research artifacts. Reproductions use invented identities and data only.

## Main conclusion

Token Horizon already has useful personal and community analytics primitives. Track 5 should establish a consistent scoped query contract and coverage-aware values before building team/admin cost dashboards. Three distinct data planes must remain explicit: native snapshot publication; Go metered/event storage with a configurable cloud outbox; and local gateway traces. None of the inspected sources establishes that the latter two feed the currently public Cloudflare dashboard.

The most consequential current limitations are hidden costs encoded as zero, membership-based team totals being mistaken for spend allocation, incomplete request/time denominators, sparse-date range handling, and profile/report controls being mistaken for enterprise tenant/RBAC enforcement. The already implemented history replacement, stale snapshot rejection and CAS write handling should be extended, not recreated.

## 1. Actual data lineage

### 1.1 Native Swift snapshot/publication path

`UsageEngine` combines OpenCode SQLite, additive provider JSONL, stateful Codex/Kimi parsing, and local Ollama measurements. Its public DTO contains per-tool/per-model totals, projects, recent sessions, daily model history, collection time, and parser health. Snapshot scalar defaults are zero, while `updatedAt` initially defaults to distant-past. [Models.swift L11–67](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/clients/macos/Sources/TokenHorizon/Usage/Models.swift#L11-L67).

`UsageEngine.leaderboardData()` captures snapshot, daily history, heatmap and exact hourly history using one collection date and one engine lock. OpenCode/Ollama input snapshots are read once. Hourly exports include only nonzero usage/cost and preserve epoch-hour keys. [UsageEngine.swift L470–509](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/clients/macos/Sources/TokenHorizon/Usage/UsageEngine.swift#L470-L509).

Native storage includes `snapshot.json`, `history.json`, `trends.json`, `limits.json`, and versioned `engine-state.json`, gated by `historyPersistenceEnabled`. Atomic JSON writes persist these separately. Parser state version 5 preserves offsets/watermarks and includes migration behavior. This is local cache/state, not a hosted event warehouse. [DurableStore.swift L136–224](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/clients/macos/Sources/TokenHorizon/Persistence/DurableStore.swift#L136-L224).

`LeaderboardStore.syncLocal()` stages a reduced profile snapshot with privacy transformations and a collection timestamp. Automatic sync requires configuration and valid authorization; it does not enable publication merely because a view was opened. Manual sync refreshes/stages before publish and pull. [LeaderboardSyncController.swift L143–212](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/clients/macos/Sources/TokenHorizon/Leaderboard/LeaderboardSyncController.swift#L143-L212).

The Cloudflare implementation writes all published profile entries to `leaderboard.json` in R2. `updateProfileEntries` uses ETag compare-and-swap and retries up to five times; it rechecks ownership in the reducer and fails on unreadable/unacknowledged storage. [leaderboard-storage.js L1–40](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/cloudflare/src/leaderboard-storage.js#L1-L40).

### 1.2 Go event/storage path

The Go schema stores `usage_event` rows keyed by event ID, with time, machine/source/vendor/model, token classes, raw cost/cost source, account/request/session IDs, product attribution, attestation, and optional rate/context/latency values. There is no tenant ID or project ID in this event table. `file_annotation` is keyed by vendor/request ID; pricing is temporal by `valid_from`. These facts are source capability, not evidence of production ingestion. [schema.go L7–104](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/daemons/go/internal/store/schema.go#L7-L104).

`InsertMetered()` performs transactional `INSERT OR IGNORE` by UUID. Event pagination uses rowid; outbox reads `rowid > cursor`, which can capture newly inserted late events even when their event time is old. Time filters use `[from,to)`. Analytics endpoints are `/analytics/events`, `/analytics/buckets`, `/analytics/summary`, and `/analytics/count`. [store.go L71–166](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/daemons/go/internal/store/store.go#L71-L166), [query.go L50–110](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/daemons/go/internal/store/query.go#L50-L110), [api.go L198–267](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/daemons/go/internal/api/api.go#L198-L267).

The Go outbox targets configured `/ingest/events` and `/ingest/limits`, gates on BaseURL and signed-in UserID, sends an identity envelope, batches 500 records, limits one drain to 40 pages, advances the cursor only after HTTP success, serializes concurrent drains, and backs off for 60 seconds on error. An ingestion receiver and its tenant authorization/unique constraints were not located in the inspected tree. Do not equate the outbox's comment about cloud idempotence with independently inspected receiver behavior. [sync.go L109–162](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/daemons/go/internal/cloudsync/sync.go#L109-L162), [sync.go L165–327](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/daemons/go/internal/cloudsync/sync.go#L165-L327).

The Go `/stats` compatibility path explicitly leaves sessions, projects and modelDaily empty because it lacks equivalent metered data. It also chooses non-null list-price `CostEquivalent` over raw recorded cost, so consumers must not label its generic cost as an invoice or billed spend. [compat.go L27–51, L66–71](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/daemons/go/internal/api/compat.go#L27-L71).

### 1.3 Local traces

The standalone gateway explicitly excludes cloud-provider traces from usage totals because provider file parsers already count that traffic. Its in-memory ring has 200 traces, disk retains 30 day files up to 256 MiB, and stored bodies are capped at 256 KiB per side. Consequently a 168-hour stats request over the ring is not proof of complete 168-hour capture. [gateway/store.go L16–47](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/gateway/store.go#L16-L47), [L276–303](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/gateway/store.go#L276-L303).

The Go trace table is separate from usage_event, caps around 2,000 rows with pruning checked every 64 inserts, and exposes body-free summaries separately from full trace retrieval. Error rate, retry suspects, TTFT and active-time token rate are local supported metrics; they are not present in the inspected published-profile payload. A retry suspect is heuristic evidence, not a confirmed retry count. [trace.go L18–76](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/daemons/go/internal/store/trace.go#L18-L76), [L160–239](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/daemons/go/internal/store/trace.go#L160-L239).

## 3. Time, corrections, missing data and freshness

- **Native day windows:** UTC-aligned hourly buckets are grouped by `Calendar.current` local day. Daily-aligned trend bounds use calendar arithmetic for DST. The original local day epoch is retained in exports; a zero-offset UTC calendar cannot be reconstructed merely by relabelling those scalar daily values. `[from,to)` range matching on whole hour buckets still has limited boundary precision in half/quarter-hour zones; specify coarse precision rather than claiming event-exact day splits. [UsageEngine.swift L530–649](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/clients/macos/Sources/TokenHorizon/Usage/UsageEngine.swift#L530-L649).
- **Go buckets:** `SnapBucketSeconds` permits 300/900/3600/86400-second epoch buckets. The file backfill scanner explicitly uses UTC day boundaries. This differs from the Swift publisher's local-day convention. [query.go L217–241](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/daemons/go/internal/store/query.go#L217-L241), [backfill.go L3–33](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/daemons/go/internal/capture/files/backfill.go#L3-L33).
- **Native retained past:** when live prior-day totals are zero and cached history is positive, durable history overlays the day. This preserves pruned-file history but has no accompanying “retained cache” provenance flag in the point. A later correction to zero needs an explicit tombstone/known-zero policy rather than the UI assuming live completeness. [UsageEngine.swift L558–577](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/clients/macos/Sources/TokenHorizon/Usage/UsageEngine.swift#L558-L577).
- **Cloud corrections:** incoming dated buckets replace covered daily/model groups idempotently, including the membership of Other. Remote-only days remain. Impossible overlapping model splits become Other preserving the exact daily total; missing split costs are not invented. Values older than 130 days or in the future are excluded. [usage-history.js L8–105](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/cloudflare/src/usage-history.js#L8-L105).
- **Collection versus publication:** server `updatedAt` records receipt; `collectedAt` orders snapshots. Explicitly older collectedAt receives 409, while dated newer captures can correct scalar totals downward. Legacy undated payloads preserve scalar floors. [index.js L1117–1122, L1199–1203, L1296–1325](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/cloudflare/src/index.js).
- **History is not cumulative rank snapshots:** provider history uses source-dated usage; publication snapshots cannot recover missing usage dates by differencing. Ranking snapshots retain sixty records. [usage-history.js L110–136](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/cloudflare/src/usage-history.js#L110-L136), [index.js L197–225](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/cloudflare/src/index.js#L197-L225).
- **Current failure fallback:** public profile reads can fall back to default starter entries on missing/corrupt/unavailable R2. Write operations separately fail closed. Operational dashboards need an explicit unavailable/demo marker and must never interpret fallback data as tenant usage. [index.js L2198–2264](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/cloudflare/src/index.js#L2198-L2264).
- **Health evidence:** local parserHealth counts lines/parsed/suspect per source since launch; it is not included in the staged public breakdown. Hosted capture-health alerts need a new consented health export, or must remain local. [UsageEngine.swift L1983–2000](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/clients/macos/Sources/TokenHorizon/Usage/UsageEngine.swift#L1983-L2000).

The repository already documents the snapshot/receipt distinction and regression gates in [docs/sync-consistency.md](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/docs/sync-consistency.md). Do not file a duplicate “make publishing idempotent” item.

## 4. Identity, RBAC, sharing and retention

Account team membership is many-to-many and keyed by verified subject/owner. Public metadata caches live five seconds; write and share authorization use fresh records. Roles observed are owner/member. A team label or email domain cannot authorize access. These are good foundations for Track 2, but do not constitute self/manager/admin analytics privileges or event-time tenant attribution. [team-invites.js L203–217](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/cloudflare/src/team-invites.js#L203-L217), [L447–494](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/cloudflare/src/team-invites.js#L447-L494).

Published `/api/user` returns the full sanitized entry. Session titles are private by default because the publisher clears them, but metadata and top project basenames remain. For future workplace analytics, require independent consent/policy for person attribution, project naming and session timing; suppress prompt/title/body fields by server allowlist even when the source client submits them. A public profile must not be repurposed into a private employee record without a separate migration/consent boundary. [index.js L1008–1094](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/cloudflare/src/index.js#L1008-L1094), [LeaderboardStore.swift L806–919](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/clients/macos/Sources/TokenHorizon/Leaderboard/LeaderboardStore.swift#L806-L919).

Shared reports have explicit public/people/group/org scopes, expiry/revocation, privacy flags, audience checks, and `private,no-store` responses. Team-scoped report access checks fresh memberships. `allowDownload` is stored as an option at index.js L1655, but no CSV/PDF export handler or enforcement check exists in the inspected worker modules. It is a persisted setting, not evidence of a working download workflow. [index.js L1740–1757](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/cloudflare/src/index.js#L1740-L1757), [L2555–2584](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/cloudflare/src/index.js#L2555-L2584).

Retention is heterogeneous. Go usage rows are unlimited unless `TH_RETENTION_DAYS` is set, and pruning occurs on store open. Go traces are size/row-capped and age-pruned every 64 inserts when enabled. Native JSON history is bounded by caller windows and user persistence, public history by 130 days, rank snapshots by 60 records, share indices by 200, activity log by 50. No cross-layer deletion or enterprise retention guarantee was established. [store.go L30–60](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/daemons/go/internal/store/store.go#L30-L60), [trace.go L18–69](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/daemons/go/internal/store/trace.go#L18-L69), [index.js L2483–2509](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/cloudflare/src/index.js#L2483-L2509).

Proposed tenant query boundary: authorize immutable tenant/person/project scope server-side before aggregation, include policy version in cached query keys, separate aggregate and person-detail privileges, suppress small cohorts plus complementary totals, restrict low-coverage comparisons, reauthorize exports at creation and retrieval, and apply deletion to rows, rollups, cached results and pending exports. These are proposals; no implementation is claimed.

## 5. Performance and acceptance implications

The public backend reads a single complete profile document and performs in-memory sorting and aggregation; team enrichment can add R2 membership/team reads. CAS prevents lost updates but serializes contention around a shared object. This is a viable small published-community design; it is not evidence of suitability for high-volume private event analytics. Establish a cardinality envelope and benchmark before adding admin/global queries. [leaderboard-storage.js](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/cloudflare/src/leaderboard-storage.js), [index.js L874–1003](https://github.com/castlemilk/token-horizon/blob/b468206e9378c8d7a6788b67072494982e7de17d/cloudflare/src/index.js#L874-L1003).

Recommended acceptance tests, all proposed unless listed in section 6:

1. Same tenant/filter/range/granularity must reconcile KPI totals, chart bins, table totals and export manifest. Team and provider filters must not leave unrelated global totals under scoped labels.
2. Unknown/hidden/free/estimated/reported cost fixtures remain distinct; hidden cost is excluded from the known-cost numerator and its rows excluded from the denominator. Display coverage separately. Cost aggregation must reconcile effective event cost with row drilldown.
3. Week token/request average uses identical event scope and boundaries. Unsupported request counts yield unavailable, not a ratio based on all-time requests.
4. A 7-day request with observations 90 days apart excludes the old observations; missing current dates remain null unless the producer attests complete capture and zero activity. Keep sparse/zero/withheld/error states distinct through API, chart, tooltip and CSV.
5. One person in two teams counts once in tenant-wide totals, once in each membership view; an allocation view separately guarantees sum of allocated costs plus Unallocated equals tenant total. Joining must not silently reattribute historical spend.
6. DST 23/25-hour days, Melbourne midnight, Adelaide/Kathmandu fractional offsets, leap day, cross-zone clients and incomplete current day use explicit IANA zones and boundaries. Source-day legacy snapshots are labelled without pretending event-level rebucketing.
7. Repeat/delayed/full snapshot inputs preserve existing idempotence, downward corrections, conflict/ownership handling and Other reconciliation. Add data revision/correction markers to consumers; do not duplicate existing CAS/history implementation.
8. Product filters work on summary, buckets, table and export; partial annotations do not change counts or duplicate a request. Annotation join includes the intended vendor/request identity boundary.
9. Optional rate/latency observations report sample counts and exclude unsupported rows from their denominators. Error rates are over captured exchanges only, with capture coverage; retries remain suspects unless confirmed.
10. Public DTO allowlist strips all account identifiers/emails/credentials/raw titles/paths. Private report access is revoked immediately on membership loss despite warm caches. Tenant A identifiers in path/body/filter cannot expose B's totals or existence.
11. Exports snapshot a query/data revision, preserve timezone and unit semantics, include coverage and suppression metadata, escape CSV formulas, and recheck current authorization at download. `allowDownload` must become an enforced permission or be removed from the UI until implemented.
12. Retention/deletion tests cover source rows, rollups, exports, caches, persisted local state and consent withdrawal. Reports show retained coverage instead of silently treating removed dates as zero.

## 6. Checks actually performed

`check_sql.py` uses the inspected schema in an in-memory SQLite database and source-extracted query expressions, populated with two synthetic events and one synthetic annotation. It reproduced: `fa.product` unresolved without the aggregate annotation join; source generation-rate average 25 vs 50 for supported observations; raw aggregate cost 0 vs effective event cost 0.25. This is a source-expression reproduction, not a Go daemon test.

`check_cloud.mjs` evaluates the inspected pure helper bodies with synthetic records, without starting the worker.
